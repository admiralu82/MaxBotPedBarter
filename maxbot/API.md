# API Документация

REST-интерфейс бэкенда бота (`bot/api.js`). Описывает **фактическое поведение кода**, включая известные отклонения.

## Общие сведения

| Параметр | Значение |
|---|---|
| Порт | `API_PORT` из `.env` (по умолчанию `3000`) |
| Префикс API | `/api` |
| Статика SPA | `/app` → каталог `APP_DIR` (по умолчанию `./app_dir`) |
| Webhook MAX | `POST /webhook/<hash от BOT_TOKEN>` |
| Формат тела | JSON (`Content-Type: application/json`), кроме `POST /api/files` (multipart) |
| Кэширование | отключено для всех ответов (`Cache-Control: no-store`) |
| Формат ошибки | `{ "error": "<текст на английском>" }` |
| Формат успеха | `{ "success": true }` либо JSON-объект ресурса |

### Параметры идентификации в query

Имена параметров **не унифицированы** — это состояние кода, а не опечатка документации:

| Ресурс | Параметр |
|---|---|
| `groups` (DELETE) | `ID` (заглавная) |
| `users` | `user_id` |
| `files` | `file_id` |
| `notes` | `note_id`, `group_id`, `user_id` |
| `attachments` | `note_id`, `file_id` |

## Авторизация

Схема: контакт в боте → одноразовый код → обмен кода на JWT → httpOnly cookie.

```
/start → кнопка requestContact
      → message_created (attachment.type === 'contact')
      → usersDb.update(user_id, { phone })
      → authCodesDb.create(user_id, TTL 60 c)
      → ссылка ${WEBHOOK_DOMAIN}/app/auth?code=<uuid>
      → SPA: POST /api/auth/exchange { code }
      → JWT (expiresIn: 365d) в cookie BOT_AUTH51
```

- JWT подписывается `JWT_SECRET` из `.env`; если переменная не задана — используется встроенный fallback-секрет.
- Payload: `{ user_id, is_admin, iat, exp }`.
- Срок жизни токена — **365 дней** (не «бессрочный»).
- Перевыпуск — только повторной авторизацией через контакт.
- Просроченные коды удаляются `authCodesDb.cleanup()` каждые 5 минут (`bot/index.js`).

### POST /api/auth/exchange

Обмен одноразового кода на JWT. Единственный роут, исключённый из `originRestriction`.

**Тело запроса:**
```json
{ "code": "uuid-from-bot" }
```

**Ответ (200 OK):**
```json
{
    "user_id": 12345,
    "username": "john_doe",
    "first_name": "John",
    "last_name": "Doe",
    "is_admin": 0
}
```

**Cookie (устанавливается автоматически):**

| Атрибут | Значение |
|---|---|
| Имя | `process.env.AUTH_COOKIE` (`BOT_AUTH51`) |
| `httpOnly` | `true` |
| `secure` | `true` |
| `sameSite` | `strict` |
| `maxAge` | 365 дней |

**Ошибки:**
- `400` — не передан `code`
- `401` — код не найден или истёк
- `404` — код валиден, но пользователь удалён

> `secure: true` означает, что браузер не примет cookie по `http://`. Для локальной разработки нужен HTTPS или правка флага.

### Проверка авторизации

Роутов `GET /api/auth`, `/api/auth/me` и подобных **нет**. Проверить сессию можно только косвенно — по ответу защищённого роута: `403` на `PUT /api/notes` означает, что токен не распознан либо прав недостаточно.

## Матрица прав (проверена на живом сервере)

| Роут | Без токена | Пользователь (`is_admin=0`) | Админ (`is_admin=1`) |
|---|---|---|---|
| `GET /api/groups` | 200 | 200 | 200 |
| `POST /api/groups` | **403** | 403 | 201 |
| `DELETE /api/groups` | **403** | 403 | 200 / 500 (FK) |
| `GET /api/users` | 200 | 200 | 200 |
| `PUT /api/users` | **200** / 403 (`is_admin`) | 200 / 403 (`is_admin`) | 200 (кроме снятия с себя — 400) |
| `POST /api/users` | **201** | 201 | 201 |
| `GET /api/files` | 200 | 200 | 200 |
| `POST /api/files` | **201** | 201 | 201 |
| `DELETE /api/files` | **403** | 200 (файл своего материала) / 403 | 200 |
| `GET /api/notes` | 200 | 200 | 200 |
| `POST /api/notes` | **201** | 201 | 201 |
| `PUT /api/notes` | **403** | 200 (только свой) | 200 (любой) |
| `DELETE /api/notes` | **403** | 200 (только свой) | 200 (любой) |
| `GET /api/attachments` | 200 | 200 | 200 |
| `POST /api/attachments` | **403** | 200 (свой материал) / 403 | 200 |
| `DELETE /api/attachments` | **403** | 200 (свой материал) / 403 | 200 |

Жирным выделены мутации, доступные **без авторизации**. Причины:

- `authMiddleware` включён (`bot/api.js`) — `req.user` заполняется из JWT;
- `requireAuthForMutations` **выключен** — проверка «не аноним» не выполняется;
- `POST /api/notes`, `POST /api/users`, `POST /api/files` вообще не обращаются к `req.user`.

Проверено: `POST /api/users` без токена с `{"user_id":777001,"is_admin":1}` → `201`, пользователь создан с `is_admin: 1`. Повышение прав через `PUT` закрыто (см. ниже), создание пользователя с `is_admin: 1` — нет.

> **Область действия прав автора.** Изменение и удаление материала, прикрепление и открепление его файлов, удаление файлов — всё это проверяется по авторству материала (`resolveNoteEditor` в `bot/api.js`). Аноним или посторонний пользователь получает `403` на `PUT`/`DELETE /api/notes`, `POST/DELETE /api/attachments`, `DELETE /api/files`. Открытыми анонимам остаются `POST /api/notes`, `POST /api/files`, `POST /api/users` и правка профиля без `is_admin`.

## Группы (кафедры)

### GET /api/groups

Все группы. Доступно без авторизации.

**Ответ (200 OK):**
```json
[
  {
    "group_id": 1,
    "name": "Кафедра начального общего образования",
    "description": "Руководитель кафедры - Внукова Елена Александровна",
    "user_id": null
  }
]
```

### POST /api/groups

Создать группу. **Требуется `is_admin = 1`.**

**Тело запроса:**
```json
{ "name": "Новая кафедра", "description": "Описание", "user_id": 12345 }
```

**Ответ (201 Created):** объект группы (как в `GET`).

**Ошибки:**
- `403` — нет прав администратора
- `500` — ошибка БД
### DELETE /api/groups?ID=xxx

Удалить группу. **Требуется `is_admin = 1`.**

**Параметры:** `ID` — `group_id` (имя параметра — заглавными буквами, `group_id` не распознаётся).

**Ответ (200 OK):** `{ "success": true }`

**Ошибки:**
- `400` — не передан `ID`
- `403` — нет прав администратора
- `500` — удаление связанной группы нарушает `FOREIGN KEY` в `notes`

> Нет проверки каскада: при наличии материалов удаление падает с `500`, записи в `notes` остаются.

## Пользователи

### GET /api/users?user_id=xxx

**Параметры:** `user_id`

**Ответ (200 OK):**
```json
{
  "user_id": 12345,
  "username": "john_doe",
  "first_name": "John",
  "last_name": "Doe",
  "phone": "+79001234567",
  "avatar_url": "https://...",
  "is_admin": 0
}
```

**Ошибки:**
- `400` — не передан `user_id` (текст ошибки: `ID parameter is required`)
- `404` — пользователь не найден; сюда же попадает нечисловой `user_id` (`parseInt` → `NaN`)

### GET /api/users (без параметров)

Список всех пользователей. Каждый элемент дополнительно содержит `notes_count` — число материалов пользователя (`usersDb.getAllWithNoteCounts`, `LEFT JOIN notes`).

```json
[
  {
    "user_id": 12345,
    "username": "john_doe",
    "first_name": "John",
    "last_name": "Doe",
    "phone": "+79001234567",
    "avatar_url": "https://...",
    "is_admin": 0,
    "notes_count": 2
  }
]
```

> `notes_count` есть **только в списке**: `GET /api/users?user_id=` отдаёт чистую запись из `users`. Если значение нужно и там, его придётся считать отдельно.
>
> Подсчёт делается на сервере специально: иначе SPA пришлось бы запрашивать `GET /api/notes?user_id=` для каждого пользователя.

### PUT /api/users?user_id=xxx

Частичное обновление: меняются только переданные поля.

**Параметры:** `user_id`

**Допустимые поля тела:** `username`, `first_name`, `last_name`, `phone`, `avatar_url`, `is_admin`

```json
{ "first_name": "New Name", "is_admin": 1 }
```

**Ответ (200 OK):** обновлённый пользователь.

**Ошибки:**
- `400` — не передан `user_id`
- `400` — админ пытается снять права администратора с самого себя (`Admin cannot revoke own admin status`)
- `403` — в теле передан `is_admin`, а запрос не от администратора (`Only admin can change admin status`)

> **Смена статуса защищена.** Поле `is_admin` принимается только от администратора (`isAdminRequest`), и админ не может снять права с себя — иначе остался бы без доступа к управлению. Проверено: неадмин с `{"is_admin":1}` → `403`; админ на себе с `{"is_admin":0}` → `400`.
>
> Остальные поля (`first_name`, `phone` и т.д.) по-прежнему принимаются без проверки прав: аноним может переписать профиль любого пользователя. Это следствие отключённого `requireAuthForMutations`.

### POST /api/users

Создать пользователя. Поля: `user_id` (PK, обязателен), `username`, `first_name`, `last_name`, `phone`, `avatar_url`, `is_admin`.

**Ответ (201 Created):** созданный пользователь.

**Ошибки:**
- `500` — `user_id` уже существует (`UNIQUE constraint`)

> При отсутствии `user_id` в теле ответ `201` с **пустым телом**: запись не создаётся, `getById(undefined)` возвращает `undefined`. Проверки обязательных полей нет.
>
> **Проверки прав нет:** без токена можно создать пользователя с `is_admin: 1` (проверено, `201`).

## Файлы

### GET /api/files?file_id=xxx

Скачать файл.

**Параметры:** `file_id`

**Ответ (200 OK):** содержимое файла с `Content-Disposition: attachment; filename="<name>"`.

**Ошибки:**
- `400` — не передан `file_id`
- `404` — нет записи в `files`
- `404` — запись есть, но файла нет на диске (`File not found on disk`)

### POST /api/files

Загрузка файла.

**Content-Type:** `multipart/form-data`

**Поля формы:**
- `file` — файл (обязательно)
- `note` — текстовое примечание (опционально)

**Ответ (201 Created):**
```json
{
  "file_id": "1731328934567_abc123",
  "name": "document.pdf",
  "size": 102400,
  "note": "Важный документ"
}
```

- `file_id` = `Date.now() + '_' + random(36)`, формируется в multer storage.
- На диске: `${FILES_DIR}/${file_id}_${name}`.
- `name` — UTF-8 имя файла из `filename` multipart-части (`defParamCharset: 'utf8'`). Русские буквы, пробелы, `()`, `%`, `,` сохраняются как есть.
- Из имени вычищается только небезопасное для ФС: управляющие символы и `\ / : * ? " < > |` → `_`; пустое имя/`.`/`..` → `file`; имя длиннее 180 байт UTF-8 обрезается с сохранением расширения. `name` в БД и имя на диске всегда совпадают.

**Ошибки:**
- `400` — файл не передан

> Нет проверки прав, MIME-типа и размера. Файл физически сохраняется multer'ом **до** записи в БД — при ошибке БД на диске останется мусор.

### DELETE /api/files?file_id=xxx

Удалить файл с диска, запись в БД и все связанные записи в `attachments`.

**Параметры:** `file_id`

**Права:**
- админ — удаляет любой файл;
- автор — только файл, привязанный хотя бы к одному его материалу и не используемый ни в одном чужом;
- остальные — `403`. Непривязанный файл (без записей в `attachments`) удаляет только админ.

**Ответ (200 OK):** `{ "success": true }`

**Ошибки:**
- `400` — не передан `file_id`
- `403` — нет прав (не админ, не автор, файл непривязан или используется в чужом материале)
- `404` — файл не найден

> Записи в `attachments` удаляются вместе с файлом (`attachmentsDb.deleteByFileId`), осиротевших строк не остаётся.

## Материалы

### GET /api/notes?note_id=xxx

Материал по ID.

**Ответ (200 OK):**
```json
{
  "note_id": 1,
  "group_id": 3,
  "user_id": 12345,
  "name": "Методическая разработка",
  "description": "Описание материала",
  "author_username": "john_doe",
  "author_first_name": "John",
  "author_last_name": "Doe",
  "author_avatar_url": "https://..."
}
```

**Ошибки:** `404` — материал не найден.

> Поля `author_*` приходят из `LEFT JOIN users` во всех выборках материалов (`getById`, по `group_id`, по `user_id`). Автор отдаётся плоско, а не вложенным объектом, — так исторически сложился `SELECT` и это не менялось, чтобы не ломать клиентов.
>
> Если запись пользователя удалена, `user_id` останется, а `author_*` будут `null` — SPA в этом случае подпись автора не показывает.

### GET /api/notes?group_id=xxx

Все материалы группы — массив объектов.

**Ответ (200 OK):** `[ { "note_id": 1, ... } ]`, для пустой группы — `[]`. В каждом элементе есть поля `author_*` (см. выше).

> Нечисловой `group_id` (`?group_id=abc`) даёт `200 []`, а не `400`: `parseInt` → `NaN`.

### GET /api/notes?user_id=xxx

Все материалы пользователя — массив объектов с теми же полями `author_*`.

**Ошибки:**
- `400` — не передан ни один из `note_id` / `group_id` / `user_id`

Приоритет при нескольких параметрах: `note_id` → `group_id` → `user_id`.

### POST /api/notes

Создать материал.

```json
{
  "group_id": 3,
  "user_id": 12345,
  "name": "Новый материал",
  "description": "Описание материала"
}
```

**Обязательные поля:** `group_id`, `user_id`, `name` (ограничения схемы `NOT NULL` + `FOREIGN KEY`).

**Ответ (201 Created):** созданный материал.

**Ошибки:**
- `500` — пропущено обязательное поле (тексты SQLite: `NOT NULL constraint failed`, `FOREIGN KEY constraint failed`)
- `500` — `group_id` или `user_id` не существует

> Валидации тела нет, поэтому ошибки клиента отдаются как `500`, а не `400`.

### PUT /api/notes?note_id=xxx

Обновить материал. По замыслу доступно **автору** или **администратору**.

**Параметры:** `note_id`

**Тело (любое подмножество):**
```json
{ "group_id": 4, "name": "Уточнённое название", "description": "Обновлённое описание" }
```

`user_id` (автор) изменить нельзя — поле вырезается из тела в обработчике.

**Ответ (200 OK):** обновлённый материал. Пустое тело — тоже `200`, без изменений.

**Ошибки:**
- `400` — не передан `note_id`
- `404` — материал не найден
- `403` — запрос не от автора и не от администратора

> `401` этот роут не возвращает: `requireAuthForMutations` отключён, а собственной проверки «не аноним» в обработчике нет — аноним получает `403`.
>
> Проверено: автор со своим JWT → `200`; администратор на чужом материале → `200`; другой неадмин → `403`; без токена → `403`.

### DELETE /api/notes?note_id=xxx

Удалить материал. **Доступно автору материала или администратору.**

**Параметры:** `note_id`

**Ответ (200 OK):** `{ "success": true }`

**Ошибки:**
- `400` — не передан `note_id`
- `403` — запрос не от автора и не от администратора
- `404` — материал не найден

> Бэкенд сам снимает связи в `attachments` и удаляет файлы, которые после этого не принадлежат ни одному материалу (с диска и из `files`). Раньше здесь оставались осиротевшие строки, а удаление с вложениями падало на `FOREIGN KEY`.
>
> Аноним получает `403`, а не `401`: `requireAuthForMutations` отключён, проверка идёт по `resolveNoteEditor`.

## Вложения

### GET /api/attachments?note_id=xxx

Вложения материала.

**Ответ (200 OK):**
```json
{
  "note_id": 1,
  "note": {
    "note_id": 1,
    "group_id": 3,
    "user_id": 12345,
    "name": "Материал",
    "description": "Описание"
  },
  "files": [
    { "file_id": "1731328934567_abc123", "name": "document.pdf", "size": 102400, "note": "Приложение 1" }
  ]
}
```

**Ответ при отсутствии вложений и/или материала (200 OK):**
```json
{ "note_id": 999, "note": null, "files": [] }
```

**Ошибки:** `400` — не передан `note_id`.

> По ответу нельзя отличить «материала нет» от «материал есть, вложений нет»: `attachmentsDb.getByNoteId()` возвращает `null` в обоих случаях. Нужен либо `404` для отсутствующего материала, либо отдельный флаг.

### POST /api/attachments?note_id=xxx&file_id=xxx

Прикрепить файл к материалу. Повторное прикрепление — no-op (`INSERT OR IGNORE`), ответ тот же.

**Права:** автор материала или админ.

**Ответ (200 OK):** `{ "success": true }`

**Ошибки:**
- `400` — не передан `note_id` или `file_id`
- `403` — материал принадлежит другому пользователю
- `404` — материал не найден
- `500` — файл не существует (`FOREIGN KEY constraint failed`)

### DELETE /api/attachments?note_id=xxx&file_id=xxx

Открепить файл от материала (сам файл остаётся в `files` и на диске).

**Права:** автор материала или админ.

**Ответ (200 OK):** `{ "success": true }` — даже если связи не было.

**Ошибки:**
- `400` — не передан `note_id` или `file_id`
- `403` — материал принадлежит другому пользователю
- `404` — материал не найден

> Чтобы удалить файл целиком, после открепления нужен `DELETE /api/files`.

## Middleware и безопасность

### Текущее состояние (важно)

```js
// bot/api.js:65-66
app.use('/api', authMiddleware);
// app.use('/api', requireAuthForMutations);
```

- `authMiddleware` — **включён**: `req.user` заполняется из JWT, если токен валиден.
- `requireAuthForMutations` — **выключен**: анонимные мутации не отсекаются.

Следствия:

| Следствие | Роуты |
|---|---|
| `is_admin` проверяется по `req.user` | `POST/DELETE /api/groups`, `DELETE /api/files`, смена `is_admin` в `PUT /api/users` |
| Авторство материала проверяется по `req.user` | `PUT`/`DELETE /api/notes`, `POST/DELETE /api/attachments`, `DELETE /api/files` |
| Мутации без авторизации | `POST /api/users`, `POST /api/notes`, `POST /api/files`; `PUT /api/users` — кроме поля `is_admin` |
| Эскалация прав | `POST /api/users` принимает `is_admin` от анонима (`PUT` больше не принимает) |
| `401` не отдаётся ни одним защищённым роутом | все |

Активны два middleware: `originRestriction` и `authMiddleware`.

### `originRestriction` (активен)

Применяется ко всему `/api`, кроме `/api/auth/exchange`.

- Нет заголовка `Referer` → пропуск (curl, серверные вызовы)
- `Referer` с `host`, совпадающим с `Host` → пропуск
- Иначе → `403 { "error": "Access denied" }` + запись в лог

Защита слабая: `Referer` подделывается тривиально. Реальный барьер — httpOnly cookie с `sameSite=strict`.

### `authMiddleware` (включён)

Читает JWT из cookie `AUTH_COOKIE`, верифицирует, кладёт `req.user = { user_id, is_admin, iat, exp }`. Не блокирует — при отсутствии/невалидности токена ставит `req.user = null` и пишет предупреждение в лог.

### `requireAuthForMutations` (отключён)

Блокировал бы `POST/PUT/PATCH/DELETE` без валидного JWT ответом `401`. GET разрешены всем. Включение сделает `POST /api/users`, `POST /api/notes` и `POST /api/files` недоступными анонимам — это закроет оставшуюся эскалацию прав через `POST /api/users`, но потребует авторизации для всех мутаций из SPA.

### CORS

`cors` установлен в зависимостях, но `app.use(cors())` закомментирован (`bot/api.js:37`). Заголовки `Access-Control-Allow-*` не отдаются; SPA должна обслуживаться с того же origin.

## Коды ошибок

| Код | Когда |
|---|---|
| `400` | Не передан обязательный query-параметр или тело (в `POST /api/notes` — нет, там `500`); админ снимает права с себя |
| `401` | Только `POST /api/auth/exchange` (невалидный/просроченный код). Защищённые роуты отдают `403`, а не `401` — `requireAuthForMutations` отключён |
| `403` | Нет `is_admin`; внешний `Referer`; изменение/удаление чужого материала; смена `is_admin` не админом; удаление чужого файла |
| `404` | Ресурс не найден (`users`, `files`, `notes`, файл на диске) |
| `500` | Нарушение ограничений SQLite (NOT NULL, FOREIGN KEY, UNIQUE) — вместо `400`; прочие ошибки БД |

---

## Отсутствующие роуты

Требуются по спецификации, но не реализованы:

- `POST /api/auth/logout` — сброс cookie
- `PUT /api/groups` — обновление группы (есть только `groupsDb.update()` в коде)
- `PUT /api/files` — обновление метаданных файла (есть только `filesDb.update()`)
- `GET /api/files` без `file_id` — список файлов (`filesDb.getAll()` не используется)

Реализовано дополнительно, вопреки более ранней версии документа: `GET /api/auth/me` (профиль + cookie `USER_INFO`), `GET /api/users` без `user_id` (список), редирект `GET /app/auth` → `/app/#/auth`.

## Примеры использования

### Авторизация через curl

```bash
# 1. Получить код: отправить боту контакт и взять code из ссылки

# 2. Обменять код на токен
curl -X POST https://bot.v.lab31.ru/api/auth/exchange \
  -H "Content-Type: application/json" \
  -d '{"code":"your-code-here"}' \
  -c cookies.txt

# 3. Использовать токен в последующих запросах
curl https://bot.v.lab31.ru/api/groups \
  -b cookies.txt
```

### Загрузка файла

```bash
curl -X POST https://bot.v.lab31.ru/api/files \
  -b cookies.txt \
  -F "file=@document.pdf" \
  -F "note=Важный документ"
```

### Создание материала

```bash
curl -X POST https://bot.v.lab31.ru/api/notes \
  -b cookies.txt \
  -H "Content-Type: application/json" \
  -d '{
    "group_id": 3,
    "user_id": 12345,
    "name": "Методическая разработка",
    "description": "Материалы для урока"
  }'
```

### Прикрепление файла к материалу

```bash
curl -X POST "https://bot.v.lab31.ru/api/attachments?note_id=1&file_id=1731328934567_abc123" \
  -b cookies.txt
```

### Проверка ограничения по origin

```bash
# Будет 403: внешний Referer
curl -H "Referer: https://evil.com/" https://bot.v.lab31.ru/api/groups
```
